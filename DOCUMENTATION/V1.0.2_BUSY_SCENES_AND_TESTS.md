# V1.0.2: crowded platform scenes

## Outcome

V1.0.2 accelerates the shared processing used by every room in levels 1 and 5. The implementation has no room-specific condition or enemy-count reduction. It keeps the V1.0.1 renderer, cache keys, source game state machines and hardware clock/timer configuration. The work targets the user's observation that crowded scenes slow down more than empty scenes.

The accepted baseline is the exact V1.0.1 normal and diagnostic release supplied in REFERENCE_V1.0.1. All figures below compare against that baseline, rather than against an older M12/M15/M17 build. Measurements use the same pinned NGPCraft core as V1.0.1, commit c769b511dc54f4d72f22d4699cfbb5cd68aa14a2, with `set_timing_silicon()` and its clean-room HLE BIOS. Repository: https://github.com/Tixul/Ngpcraft_emulator . Neither MAME nor a physical console was used in this pass.

## Specific changes

**Actor preflight.** `platform_actor_enter()` reads the ordinary actor record and camera coordinates directly, performs the original wrapping bounds/respawn-bit checks, and publishes the same translated registers and live flags once. It batches empty records with the original cursor/count results. Every accepted enemy still enters the same original AI routine. Unusual register/stack or off-range cases retain the original instruction path.

**Projectile-to-enemy scans.** `platform_projectile_actors()` checks all ten actor slots in the original descending order. Native word operations replace repeated sparse-memory lookups and intermediate global flag stores. At either hit or exhausted continuation, the data/address registers, condition flags and tested actor are identical. Collision dimensions, signed-wrap behaviour and hit order are retained.

**Actor draw boundary.** `platform_actor_draw()` combines the ordinary MOVEM/BSR/draw/RTS/MOVEM boundary around the existing draw callback. It retains the exact emulated stack bytes, appends the same BobDraw, sign-extends restored registers exactly as the original MOVEM.W does, and continues at the original source return site. It has a fallback for unusual stack addresses. It does not merge, hide or remove enemies or fragments.

**Read-only animation tables.** Word reads whose two bytes are proven to be immutable source tables read those bytes directly in their original order. Dynamic actor/shot/global state, special device/player-state words, Cathedral sparse history, sparse map cells, aliases and boundary-straddling words retain the original mapper. This removes two rounds of generic byte mapping from many repeated animation/frame/collision table reads.

All entry points are used by the shared level-1 and level-5 executors. No table artwork or enemy placement is edited. The normal and diagnostic builds both contain the changes. Vehicle/puzzle gameplay code is unchanged and their replay rates remain equal to V1.0.1.

## Crowded-scene processing evidence

A separate breakpoint capture measures cycles from `perf_before_step` entry to `perf_after_step` entry, including intervening interrupts. It compares the same states at the same update indices and groups by active actor records at the start of the update. Actor records can also represent dynamic objects; the count is not asserted to be a count of visible enemies alone.

Level 1's replay naturally reaches five active records for 21 updates. In that group, mean gameplay-processing cost falls from about 324,473 to 273,167 cycles: a **15.81% reduction** (18.78% greater processing throughput). At four records, the reduction is about 16.38%; at three, 16.07%. Level 5 holds three records for 299 sampled updates and shows about 14.44% less processing cost. The initial zero-record update is excluded from these crowded-scene claims.

This processing interval excludes later rendering/presentation work, so it must not be substituted for whole-game FPS. The separate uninstrumented cadence trial is the overall ~12% result. Raw timings and group calculations are supplied in EVIDENCE/V102/BUSY_SCENE_PROCESSING.json and the compressed timing captures.

## Memory and compatibility

The outer RenderWork union remains 6,568 bytes and the platform's data fits below offset 2,560. Hot enemy kernels use its stage-owned tail. The old conservative 3,720-byte overlay bound is updated to the actual 4,008 bytes available in that unchanged union. A compile-time assertion checks the layouts and both builders enforce the revised bound. The less frequent rope-drawing function executes from ROM to make space for the enemy kernels; its geometry, patterns and output are unchanged.

- normal: platform overlay 3892 of 4008 bytes, leaving 116 bytes.
- diagnostic: platform overlay 3911 of 4008 bytes, leaving 97 bytes.

This adds no BSS allocation and borrows no audio or native-stack memory. Oversized overlays and overlaps with runtime/BIOS workspace fail the build. Save layouts, M68K continuation addresses, ranking/anti-farming rules and QR payload formats are unchanged. The complete second 2 MiB ROM window is byte-identical to V1.0.1, and reserved save/BIOS sectors ship erased. Existing sampled audio, credits and artwork are preserved.

## Verification completed

- Final diagnostic, all five stages, sound ON and OFF: 3,000 captured states and 3,000 resolved committed graphics surfaces match V1.0.1. States include Game, stage workspace, translated data/address registers and flags; graphics include committed maps, palettes and resolved sprite patterns. This covers the fixed first 300 updates of each route, not every later room or a naturally completed campaign.
- 180,000 host cases compare the exact original lifted blocks against the new actor-preflight, projectile-scan and actor-draw paths. They include register high words, signed boundaries, old respawn flags, partial/exhausted tables, stack contents, draw capacity and draw descriptors.
- 152,064 word reads compare the new direct-table paths with the original mappers across every low-address word start, odd addresses, mutable/special boundaries, aliases and Cathedral sparse state.
- 33,060 calls compare the actual Toshiba-compiled word accessor code against the V1.0.1 target code in NGPCraft. A known 0xA55A read also verifies that the fixture observes the correct return register.
- Normal ROM: checkpoint/respawn anti-farming, improvement-only rewards, real flash Save, cold Continue, continued-retry protection, positive QR generation, zero-score upload blocking, persistent Records reset and shared credits sequence pass. This fixture injects scores/death waits at game-tick boundaries; it is not a claim of a naturally played full game or online score submission.
- Eight existing host anti-farming tests pass. The actual generated normal-ROM QR payload independently decodes with valid checksum/formula.
- Unchanged vehicle kernels pass 400 road and 200 midpoint boundary cases on the normal ROMs, in addition to vehicle replay comparisons.
- Both final ROMs compile/link/convert successfully with the bundled Toshiba toolchain under its Linux compatibility runner. Native Windows execution was unavailable; the included Windows launcher/converter is updated but not claimed as executed on Windows.

No physical-console result is claimed. Test the busiest opening route, later crowded scenes, ropes/projectiles, deaths/checkpoints and Cathedral scrolling on the stock NGPC. Compare V1.0.1 and V1.0.2 diagnostics with the same sound setting. The expected performance gain remains an emulator finding until that comparison is made.

## Build, repeat and inspect

Use the root README for builds and the V1.0.1 optimisation document for the pinned native-core compilation command. New host tests require gcc. Run these from the extracted release root:

```sh
python3 SOURCE/tools/test_platform_enemies.py --out host-enemy-results
python3 SOURCE/tools/test_platform_word_reads.py --out host-word-results
python3 SOURCE/tools/test_platform_native_reads.py --emulator /absolute/path/ngpcraft_emulator --baseline-rom REFERENCE_V1.0.1/Batman_V1.0.1_Diags.ngc --baseline-map REFERENCE_V1.0.1/diagnostic.map --rom OUTPUT/Batman_V1.0.2_Diags.ngc --map EVIDENCE/V102_DIAGNOSTIC_BUILD/batman.map --out native-word-results.json
python3 SOURCE/tools/bench_ngpcraft.py --emulator /absolute/path/ngpcraft_emulator --rom OUTPUT/Batman_V1.0.2_Diags.ngc --map EVIDENCE/V102_DIAGNOSTIC_BUILD/batman.map --out trial.json --stages 1,2,3,4,5
python3 SOURCE/tools/capture_ngpcraft.py --emulator /absolute/path/ngpcraft_emulator --rom OUTPUT/Batman_V1.0.2_Diags.ngc --map EVIDENCE/V102_DIAGNOSTIC_BUILD/batman.map --out capture-new
python3 SOURCE/tools/compare_ngpcraft.py --baseline EVIDENCE/V102/baseline_capture --candidate capture-new --out comparison.json
python3 SOURCE/tools/capture_platform_timing.py --emulator /absolute/path/ngpcraft_emulator --rom OUTPUT/Batman_V1.0.2_Diags.ngc --map EVIDENCE/V102_DIAGNOSTIC_BUILD/batman.map --out timing-new --stages 1,5
```

Repeat benchmark and capture commands with `--sound-off` and the corresponding baseline_capture_off directory. For the A/B benchmark, run the same command with the V1.0.1 diagnostic and matching map. The source patch and staged experiment results are included. Intermediate hashes describe cumulative experiments; final acceptance uses the identities below.

The reusable lesson is to isolate an entire equivalent actor operation, retain its input/output/register/flag/stack contract, and publish final results once. Prove read-only table ranges including word boundaries before bypassing a sparse mapper. Keep all original AI and collision updates. Use crowded real replay states for performance claims and synthetic boundary fixtures for correctness. The existing extensive NGPC_PORT_OPTIMISATION_TEMPLATE.md remains included.
